# 동현정 — 개인 웹사이트

흰 바탕, 고운바탕 + EB Garamond, 프리드리히 그림과 글을 중심으로 만든 Next.js 사이트입니다. 디자인 기준은 [개발 계획 및 디자인 가이드](WEBSITE_PLAN_AND_DESIGN_GUIDE.md)에 있습니다.

## 실행

```sh
npm ci
npm run dev
```

`http://127.0.0.1:3000`에서 확인합니다. 현재는 2026-11-08에 연결 도구로 가져온 메인과 글 22개의 스냅샷을 사용합니다. 새 글이 자동으로 들어오는 상태는 아닙니다. Thoughts에 `Published` 체크박스를 추가했고 기존 공개 글 22개는 체크했습니다. 본문은 수정하지 않았습니다.

```sh
npm run typecheck
npm test
npm run build
```

## 실제 Notion 동기화 연결

1. Notion 공식 연결을 만들고 사이트 루트와 Thoughts 데이터 소스에 읽기 권한을 부여합니다. 대화에서 사용한 Notion 연결 도구의 권한은 배포 앱에 자동 전달되지 않습니다.
2. Thoughts에 `Published` 체크박스를 추가하고 웹사이트에 공개할 글만 체크합니다. 새 글은 체크 전까지 공개되지 않습니다. 원본을 모두 공개하는 코드 우회는 없습니다.
3. `.env.example`을 `.env.local`로 복사합니다. `NOTION_TOKEN`을 설정합니다. 토큰을 설정한 이후 최초 동기화 전에는 스냅샷 대신 비공개 상태로 시작합니다.
4. 로컬에서는 `npm run sync:notion`으로 처음 읽습니다. 로컬 데이터·미디어는 `.data/`에 저장됩니다. 변경 감지는 배포 후 웹훅을 연결해야 자동 실행됩니다.
5. Vercel에 배포할 때 Upstash Redis, **private** Vercel Blob을 연결합니다. 이 저장소 설정 없이 서버리스 환경에 동기화 결과를 저장할 수 없습니다. 관련 환경 변수는 `.env.example`에 나열되어 있습니다.
6. `CRON_SECRET`을 충분히 긴 임의 문자열로 정하고 보호된 `POST /api/sync`를 호출해 최초 동기화를 실행합니다. Bearer 인증이 필요합니다. 운영 상태는 같은 인증으로 `GET /api/sync?status=1`에서 확인합니다.
7. 공식 Notion 연결의 Webhooks에 `https://실제주소/api/notion/webhook`을 등록합니다. `page.content_updated`, `page.properties_updated`, `page.created`, `page.deleted`, `page.undeleted`, `page.moved`, 데이터 소스 변경 이벤트를 구독합니다.
8. Notion이 처음 전달한 verification token은 외부에 노출하지 않고 서버 저장소의 `webhook-verification`에 보관합니다. 신뢰할 수 있는 관리 환경에서 값을 읽어 Notion 구독 확인에 입력하고, 같은 값을 `NOTION_WEBHOOK_SECRET`으로 설정합니다. Redis 키에는 `donghyeon:` 접두사가 붙습니다. 이 토큰을 공개 로그나 웹페이지에 붙이지 마세요.
9. `vercel.json`에 복구용 `GET /api/sync` 스케줄을 등록했습니다. 현재 Vercel Hobby 요금제의 하루 한 번 제한에 맞춰 UTC 18시(한국 시간 다음 날 03시대)에 실행하도록 설정했습니다. 배포가 완료되어야 실제 스케줄이 활성화됩니다. 평소 수정은 웹훅으로 반영하며, 정기 작업은 웹훅 누락·작업 중단을 복구합니다.
10. 본문 수정·새 글·공개 해제·삭제를 각각 검증합니다. 배포 전 그림 파일의 출처와 이용 조건도 확인합니다.

웹훅은 이벤트를 영속 저장한 후 202를 반환하고, `after()`에서 작업을 처리합니다. 응답 이후 실행이 중단되어도 저장한 작업이 남습니다. 재확인 작업이 있어야 자동 복구가 완결됩니다. 전체 사이트를 다시 읽는 방식으로 데이터 규모가 커지면 페이지별 증분 동기화로 전환할 수 있습니다.

## 구현상 중요한 동작

- 데이터 소스와 사이트 루트만 읽고, 모든 새 글은 `Published`가 명시적으로 체크된 경우만 공개합니다.
- 본문을 끝까지 정상 조회한 버전만 저장합니다. 공개 해제는 본문 수집보다 먼저 반영합니다.
- 삭제 이벤트는 제한 표시를 먼저 기록해 진행 중이던 오래된 동기화가 글을 되살리지 못하게 합니다.
- 동기화 결과는 요청마다 읽습니다. 첫 버전에서는 영속 데이터 사본을 사용하고 Next.js의 교차 요청 페이지 캐시는 사용하지 않아 공개 해제 시 오래된 HTML이 남는 문제를 줄였습니다.
- 이미 열린 탭의 내용을 강제로 바꾸지는 않습니다. 동기화 후 새 방문·새로고침에 반영됩니다.
- 미디어는 현재 공개 콘텐츠의 참조를 확인한 뒤 제공하며 `private, no-store`를 사용합니다. 이관한 seed 이미지도 정적 public 경로로 노출하지 않습니다.
- 외부 이미지 호스트와 블록 종류는 제한합니다. 미지원 블록은 동기화를 실패시켜 기존 본문이 조용히 누락되지 않도록 합니다. 추가 블록이 필요하면 `src/lib/notion.ts`에서 지원합니다.
- 하단은 이메일 입력과 Subscribe 버튼만 제공합니다. Substack의 실제 embed 폼에서 확인한 `POST /api/v1/free?nojs=true`로 제출하며, 응답과 가입 확인은 Substack에서 처리합니다. 사이트가 가입 성공을 판정해 가짜 완료 메시지를 보여주지는 않습니다.

## 배포 전 남은 설정

Vercel 전용 프로젝트 `donghyeon-jeong`과 Tokyo 리전의 private Blob 저장소는 생성했습니다. Published 속성과 기존 22개 글의 공개 설정도 완료했습니다. Redis는 무료 요금제로 준비 중이며 약관 동의 전에는 생성하지 않았습니다. Notion 전용 연결도 개발자 약관 동의 전입니다. Notion 토큰·Redis 연결, 최초 동기화, 배포, 웹훅 검증 및 실제 `.com` 도메인은 아직 완료하지 않았습니다. `NEXT_PUBLIC_SITE_URL`은 프로덕션 주소에만 설정합니다. 값이 없으면 검색엔진 색인을 차단합니다. 도메인 등록·갱신 및 호스팅·저장소 비용은 서비스와 요금제 선택 후 확인해야 합니다.

## 파일

- `src/app/`: 홈, 글 상세, 404, API, 사이트맵
- `src/components/`: 상단 링크, 본문·인용, 소셜 로고
- `src/lib/`: Notion 조회·정규화, 영속 상태, 웹훅·작업 처리
- `src/content/`: 초기 콘텐츠 스냅샷과 비공개 경로의 seed 이미지
- `public/fonts/`: 자체 호스팅한 웹폰트와 OFL 라이선스
- `tests/core.test.ts`: 서명·공개 정책·렌더링·동기화·복구 테스트

사이트는 Node.js 서버 기능이 필요합니다. 정적 export로 배포하면 Notion 웹훅과 동기화를 사용할 수 없습니다. 본 프로젝트는 가이드에서 정한 Next.js/Vercel 구조로 구현했으며 별도 Sites 호스팅 형식으로 변환하지 않았습니다.
